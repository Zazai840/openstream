# Whisper.cpp accuracy controls in OpenStream

Research for [issue 142](https://github.com/Nabzx/openstream/issues/142). The next measurement is [issue 144](https://github.com/Nabzx/openstream/issues/144).

This report inventories controls. It does not select a product configuration.

## Short answer

OpenStream currently starts a resident `whisper-server` with only the model path, loopback host, and port. The adapter uploads a completed WAV and asks for ordinary JSON text. It sends no language, prompt, decoder, fallback, VAD, segmentation, or confidence setting. The server therefore uses the defaults compiled into the pinned server source, including English, greedy decoding, temperature `0`, temperature increment `0.2`, no VAD, and `base.en` from the app's artifact manifest. See the [current command](https://github.com/Nabzx/openstream/blob/cb7161c/electron/whisperServer.js#L7-L17), [adapter](https://github.com/Nabzx/openstream/blob/cb7161c/electron/transcriptionHttpAdapter.js#L7-L16), and [pinned server defaults](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L72-L131).

The most useful benchmark split is therefore not "which switch is best?" It is: model and quantization, prompt versus no prompt, decoder and fallback variants, VAD and segmentation variants, and whether verbose output can identify errors without adding unacceptable latency. The upstream sources establish that these controls exist and how they behave. They do not establish which one wins on OpenStream's microphone speech or stays inside the one-second Dictation latency budget.

## What is deployed now

- The app supervises `resources/bin/whisper-server` on `127.0.0.1:8178` and points it at `resources/models/ggml-base.en.bin`. The command line is `--model`, `--host`, and `--port` only. [OpenStream `electron/whisperServer.js`](https://github.com/Nabzx/openstream/blob/cb7161c/electron/whisperServer.js#L7-L17)
- The build fetches whisper.cpp tag `v1.9.3` and checks out commit `371b5a7561823ab2bb32142d2751e35e7534727b`. It builds the `whisper-server` target in Release mode with Metal enabled, examples enabled, and tests disabled. [OpenStream model artifact manifest](https://github.com/Nabzx/openstream/blob/cb7161c/scripts/model-artifacts.mjs#L11-L36)
- The vendored checkout reports the same revision locally, `v1.9.3`. The pinned upstream [CMake file](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/CMakeLists.txt#L1-L19) identifies the release version, while the app build configuration supplies the Metal and server options.
- Each request is a multipart POST containing `file=dictation.wav` and `response_format=json`. The adapter returns only `body.text.trim()`, so it discards segments, tokens, probabilities, timestamps, and language information. [OpenStream adapter](https://github.com/Nabzx/openstream/blob/cb7161c/electron/transcriptionHttpAdapter.js#L7-L16)
- The server's default request parameters are English, greedy strategy, `best_of=2`, `beam_size=-1`, `temperature=0`, `temperature_inc=0.2`, `no_speech_thold=0.6`, token timestamps enabled, VAD disabled, and `no_context=true`. The server maps these parameters into `whisper_full_params` for every request. [Pinned server defaults](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L72-L131) and [inference setup](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L913-L967)
- `n_processors` remains `1`, so the server's call to `whisper_full_parallel` takes the single-processor path and calls `whisper_full` rather than splitting the recording. [Pinned implementation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7811-L7820)

## Model and quantization choices

The pinned model documentation lists these English model sizes: `tiny.en` at 75 MiB, `base.en` at 142 MiB, `small.en` at 466 MiB, and `medium.en` at 1.5 GiB. The README's approximate resident memory figures for the corresponding size families are 273 MB, 388 MB, 852 MB, and 2.1 GB. [Pinned model table](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L42-L63) and [memory table](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/README.md#L132-L140)

The upstream project supports integer quantization for ggml Whisper models, says quantized models need less memory and disk space, and says they may be processed more efficiently depending on hardware. Its example creates a `base.en-q5_0` model with the `quantize` tool. [Pinned quantization documentation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/README.md#L157-L172)

The model catalog marks names containing `.en` as English-only and names without `.en` as multilingual. It lists pre-converted q5 examples for several large models, but does not publish a q5 accuracy or latency result for OpenStream's Mac hardware. [Pinned model notes](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L44-L63)

Practical candidates for issue 144 are therefore the current `base.en` control, `tiny.en`, `small.en`, and quantized builds of the relevant English models, with `medium.en` as a memory and latency stress case rather than an assumed fit. This is a benchmark candidate list, not a recommendation. Upstream documents size, memory, and quantization behavior, but it does not prove that any candidate meets OpenStream's under-one-second end-of-speech-to-cursor budget. The benchmark must measure warm and cold latency on the available Apple Silicon machine.

The current build enables Metal but does not enable the separately documented Core ML path. Upstream says Core ML can speed the encoder on Apple Silicon, while also warning that the first device run is slow during compilation. That is a separate build and artifact candidate, not a free runtime switch in the current binary. [Pinned Core ML documentation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/README.md#L174-L227) and [OpenStream build flags](https://github.com/Nabzx/openstream/blob/cb7161c/scripts/model-artifacts.mjs#L21-L29)

## Controls exposed by the server

The server accepts multipart fields per request. The complete mapper is in [server.cpp](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L480-L627), and the corresponding upstream HTTP example shows file, temperature, temperature increment, prompt, carry-initial-prompt, and response format fields. [Server request example](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/README.md#L73-L85)

### Language and prompt context

- `language` accepts a language name or code, and `detect_language` requests automatic detection. The server's startup default is `en`. [Server options and parser](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L163-L166) and [request fields](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L560-L567)
- A non-multilingual model forces the language back to English and disables translation. Thus language auto-detection or non-English transcription requires a multilingual model; it cannot turn the current `base.en` artifact into a multilingual model. [Pinned server handling](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L893-L900) and [model catalog](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L63-L63)
- `prompt` is an initial text prompt. whisper.cpp tokenizes it and uses at most half the model's text-context capacity, typically 224 tokens. `carry_initial_prompt` keeps the prompt in every decode window, but the public API warns that this may reduce conditioning on previous text. [Pinned public contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L520-L530) and [prompt preparation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6942-L6979)
- An initial prompt is the available server-level vocabulary-biasing mechanism. The source describes it as decoder context, not a weighted hotword list or forced vocabulary. The server exposes no `hotwords`, bias weights, or term list. The lower-level API does expose a logits filter and grammar rules, but the server request mapper does not populate either, and the server help does not expose them. [Public API fields](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L577-L590), [server request mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L480-L627), and [CLI help](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L138-L194)

For technical identifiers, the measurable question is whether a short, relevant prompt improves exact names, symbols, digits, and casing without causing vocabulary hallucinations elsewhere. The upstream source does not provide that accuracy guarantee. It explicitly clears past prompt context on a very short final audio segment because the context can make the decoder repeat or hallucinate text. [Pinned decoder source](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7062-L7067)

### Decoding and temperature fallback

- `beam_size` selects beam search when greater than one. Otherwise the server uses greedy decoding. `best_of` controls the number of greedy candidates and also participates in the beam-search decoder setup. [Server strategy setup](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L913-L945) and [public strategy contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L457-L473)
- The request can set `temperature`, `temperature_inc`, `entropy_thold`, `logprob_thold`, and `no_speech_thold`. With a positive increment, whisper.cpp tries temperatures `t`, `t + increment`, and so on up to `1.0`. [Request fields](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L518-L528) and [temperature schedule](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6888-L6897)
- A non-final temperature is rejected for fallback when decoding failed, or when average log probability is below its threshold while no-speech probability is below its threshold. Entropy can also mark a long result as failed. These are fallback tests, not calibrated word-error probabilities. [Pinned fallback logic](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7561-L7608)
- The server parser accepts `--no-fallback`, but the pinned server source never copies `params.no_fallback` into `whisper_full_params` and never uses it to change the temperature increment. The HTTP contract has no `no_fallback` field. A no-fallback benchmark condition therefore has to express that behavior through `temperature_inc=0`, subject to verification against the exact binary. [Parser and field](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L88-L90), [parser branch](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L224-L228), and [request-to-decoder mapping](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L947-L951)

### VAD and segmentation

- VAD is a server option, with a separate VAD model path plus threshold, minimum speech duration, minimum silence duration, maximum speech duration, speech padding, and inter-segment overlap. [Pinned server VAD options](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L122-L130) and [VAD help](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L185-L194)
- The request can override `vad` and those VAD numeric parameters, but not `vad_model`. When VAD is enabled, the decoder loads the path in `vad_model_path`; an empty path cannot initialize that model. The current OpenStream command supplies no VAD model path and the app manifest lists no VAD artifact, so VAD is an exposed upstream capability but not a ready current-app condition. [Request mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L596-L626), [VAD initialization](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6667-L6688), and [OpenStream command](https://github.com/Nabzx/openstream/blob/cb7161c/electron/whisperServer.js#L10-L17)
- The server exposes `offset_t`, `offset_n`, `duration`, `max_context`, `max_len`, `audio_ctx`, `split_on_word`, `no_timestamps`, and `token_timestamps`. The server converts an unset `max_len` to 60 characters before calling the decoder, and `split_on_word` matters when a maximum segment length is used. [Request mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L480-L513), [decoder mapping](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L928-L935), and [public segmentation fields](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L491-L515)
- `single_segment` and `max_tokens` exist in the lower-level public contract but are not accepted by this server's request mapper. The server also does not expose the public `suppress_regex`, grammar, or logits-filter controls. [Public contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L497-L522) and [server mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L480-L627)
- Upstream warns that `whisper_full_parallel` can reduce accuracy at the beginning and end of each chunk. OpenStream's current `n_processors=1` path avoids that explicit parallel chunk split, but a future multi-processor or client-side chunking benchmark must score boundary words separately. [Pinned public warning](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L616-L626)

There is no dedicated punctuation control in this HTTP server. Punctuation is part of decoded token text, while regex suppression and grammar are lower-level controls that this server does not expose. Punctuation and sentence boundaries therefore need their own benchmark scores rather than being inferred from word accuracy. [Token/text contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L650-L668) and [server output path](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1008-L1049)

## Confidence and uncertain-word detection

The public API exposes token text, token IDs, token probability, log probability, timestamp data, and voice length. [Pinned token data contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L131-L151) and [token getters](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L655-L682)

The server's `verbose_json` response adds segment text, start and end times, token IDs, a `words` array with token probability, temperature, average log probability, and no-speech probability. It can also add detected language probabilities unless `no_language_probabilities` is set. [Pinned verbose JSON implementation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1056-L1149)

The response calls these entries `words`, but the implementation starts one entry for each non-EOT token and only joins tokens while it is completing a UTF-8 code point. That means the `probability` field is a token probability, not a calibrated probability that the whole human word is correct. A client would need to aggregate token pieces, align them to the reference, and calibrate a threshold on real speech. This is a source-established limitation of the response shape, followed by a measurement requirement. [Pinned word-loop implementation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1101-L1137)

The current adapter requests `json`, not `verbose_json`, and throws all of these signals away. [OpenStream adapter](https://github.com/Nabzx/openstream/blob/cb7161c/electron/transcriptionHttpAdapter.js#L7-L16) The server's language-probability calculation is documented in the source as expensive, so a benchmark should record the cost of requesting verbose output and of enabling or disabling language probabilities. [Pinned server source](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1066-L1079)

## Failure modes and interactions to test

- The decoder source explicitly says that retained prompt context can make short final segments repeat or hallucinate, and clears that context in that case. Prompt tests must include both correct technical terms and unrelated speech that follows them. [Pinned prompt handling](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7062-L7067)
- The decoder detects a possible repetition loop and marks that decode as failed so fallback can try another temperature. This is a mitigation, not proof that repeated words are absent from the returned text. [Pinned repetition handling](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7436-L7442)
- Temperature fallback depends on thresholds and can add decode work. The benchmark must report both latency and whether a result used a fallback temperature. The verbose response exposes the configured segment temperature, while the source logs each failed temperature. [Pinned fallback source](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6888-L6897) and [verbose temperature field](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1140-L1145)
- Chunk boundaries can damage words at the beginning and end of a chunk. The current one-processor server path does not create those parallel chunks, but VAD segmentation, client-side chunking, and future processors can introduce a similar boundary question. [Pinned parallel warning](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L616-L626)
- Technical identifiers, numbers, casing, hyphens, and punctuation have no special accuracy guarantee in the cited whisper.cpp controls. The prompt is context, not a hard vocabulary constraint, and the server has no hotword list. Whether prompting helps or increases false insertions is an assumption requiring real speech, not a conclusion from the API. [Prompt contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L523-L530) and [server mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L568-L575)

## Facts versus assumptions

### Established by source

- The current model is `ggml-base.en.bin`, the source revision is pinned, and the binary is built with Metal. [OpenStream manifest](https://github.com/Nabzx/openstream/blob/cb7161c/scripts/model-artifacts.mjs#L11-L36)
- The adapter sends only WAV plus `response_format=json` and returns only text. [OpenStream adapter](https://github.com/Nabzx/openstream/blob/cb7161c/electron/transcriptionHttpAdapter.js#L7-L16)
- The server exposes request-level prompt, language, decoder, fallback, VAD, timestamp, and segmentation fields listed above. [Pinned request mapper](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L480-L627)
- The public library exposes token probability and verbose JSON exposes token-level fields. [Pinned public API](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L131-L151) and [server response](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1101-L1147)
- whisper.cpp documents model memory sizes, quantization behavior, prompt limits, fallback tests, repetition mitigation, and chunk-boundary accuracy risk. [Model docs](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L42-L63), [quantization docs](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/README.md#L157-L172), and [decoder source](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L7436-L7608)

### Requires real-speech measurement

- Whether `tiny.en`, `small.en`, a quantized model, or a multilingual model reaches the one-second Dictation budget while improving word, character, semantic, and technical-identifier accuracy. The upstream size and memory tables are not latency benchmarks. [Pinned model table](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L42-L63)
- Whether an initial prompt improves exact technical terms without increasing hallucinated vocabulary, repetitions, or unrelated false insertions. [Pinned prompt behavior](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6942-L6979)
- Whether greedy, beam search, `best_of`, temperature fallback, or threshold changes improve errors enough to justify their extra decode work. [Pinned decoder controls](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L536-L559)
- Whether VAD improves silence handling without dropping speech, damaging word boundaries, or adding unacceptable setup and processing cost. VAD needs a separate model path in this server. [Pinned VAD implementation](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp#L6667-L6694)
- Whether token probabilities, average log probability, entropy, and no-speech probability identify uncertain words or only uncertain segments. The server's token probabilities are not claimed to be calibrated confidence. [Pinned verbose JSON fields](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1129-L1147)
- How punctuation and sentence boundaries behave independently of word recognition, and what cleanup rules can or cannot repair after recognition has already omitted, substituted, or hallucinated speech. The cited whisper.cpp interface provides no dedicated punctuation scorer or punctuation policy. [Pinned token/text output](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/server/server.cpp#L1008-L1049)

## Benchmark candidates and constraints for issue 144

These are the smallest defensible candidate set from this research:

1. Keep the deployed `base.en` plus current defaults as the control. Record the exact model checksum, source revision, startup arguments, request fields, and server logs.
2. Compare `tiny.en`, `small.en`, and at least one q5 quantized English candidate made with the pinned `quantize` tool. Add `medium.en` only as a measured stress case if memory allows. Do not infer latency from model size alone. [Pinned model and quantization docs](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/models/README.md#L42-L63) and [quantization instructions](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/README.md#L157-L172)
3. Test prompt versus no prompt with a fixed, short vocabulary set drawn from real developer speech. Score exact technical identifiers, numbers, punctuation, and unrelated speech separately. The prompt must not be treated as a guaranteed bias list. [Pinned prompt contract](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/include/whisper.h#L523-L530)
4. Test greedy/current fallback against a small number of beam, temperature, and fallback conditions. Record fallback occurrence and latency, not only final text.
